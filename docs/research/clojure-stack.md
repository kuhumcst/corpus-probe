# Technology evaluation: Clojure(Script) web app wrapping a CLI tool (KWIC concordance over a streaming line protocol)

Research date: 2026-09-03. All versions checked against Clojars/Maven Central/GitHub on this date.

## 1. Frontend

### Replicant

- **What it is**: a data-driven rendering library for Clojure(Script) that renders hiccup to DOM nodes or strings, with zero dependencies and no React ([github.com/cjohansen/replicant](https://github.com/cjohansen/replicant), [replicant.fun](https://replicant.fun)). UI = pure function of application state; on every state change you re-render the whole app from the root and Replicant diffs.
- **Maturity**: first public release 2025.01.28; current release **2026.07.1** (`no.cjohansen/replicant {:mvn/version "2026.07.1"}`); repo pushed 2026-08-25; 529 stars, ~42.8k Clojars downloads. The README states it is "stable, performant and feature complete production quality software" whose "public APIs will not be intentionally changed" ([README](https://github.com/cjohansen/replicant)). Benchmarked via js-framework-benchmark.
- **API model**: plain hiccup (vectors/keywords/maps), pure-function components, **data-driven event handlers** (handlers can be data, globally dispatched, rather than closures), **aliases** (custom hiccup element vocabulary with side-chained data), and declarative mount/unmount transitions via `:replicant/mounting`/`:replicant/unmounting` ([replicant.fun](https://replicant.fun)). Deliberately excludes component-local state, subscriptions, and networking.
- **SSR**: `replicant.string/render` renders hiccup to a string **on the JVM or in JS** (StringBuilder-backed, 3x speedup since 2025.01.29), so you can share the exact same view functions server- and client-side ([README](https://github.com/cjohansen/replicant)). There is no React-style hydration/DOM-adoption; the first client render builds the DOM afresh [unverified — not documented either way in the README/changelog I read].
- **Companion libraries** (same author/ecosystem, all on Clojars under `no.cjohansen`):
  - **nexus 2026.08.1** — zero-dependency data-driven action dispatch: pure "expansion" handlers map actions to actions, effect handlers do side effects at the edge; placeholders like `[:event.target/value]` interpolate late-bound DOM data; interceptor hooks; wires into Replicant via `replicant.dom/set-dispatch!`; designed by Magnar Sveen, Christian Johansen, Teodor Heggelund ([github.com/cjohansen/nexus](https://github.com/cjohansen/nexus)).
  - **dataspex 2026.06.3** — point-and-click data browser / inspector (browser extension for Chrome/Firefox), inspects app state, DataScript DBs, and Nexus action logs live ([github.com/cjohansen/dataspex](https://github.com/cjohansen/dataspex)).
  - **portfolio 2026.03.1** — Storybook-style component-driven development UI, 307 stars, ~100k downloads ([github.com/cjohansen/portfolio](https://github.com/cjohansen/portfolio)).
- **Who uses it**: the official ["Replicant in the wild"](https://replicant.fun/in-the-wild/) page lists mostly small production apps — Virtuoso (virtuoso.tools), Pollariser (pollariser.eu), skipti, Datablog, Closspad — plus demos by Peter Strömberg (Calva author, a vocal adopter) and tutorial series (Parens of the Dead; Kari Marttila's [Replicant](https://www.karimarttila.fi/clojurescript/2025/02/28/clojurescript-with-replicant.html) and [Replicant+Nexus+DataScript](https://www.karimarttila.fi/clojurescript/2025/12/31/clojurescript-with-replicant-nexus-datascript.html) posts, and a [ClojureVerse starter template thread](https://clojureverse.org/t/building-a-web-app-with-replicant-an-example-template/10899)). Adoption is real but young/small-scale; the author's GitHub profile lists mattilsynet.no (Norwegian Food Safety Authority), and Replicant distills a decade of his prior dumdom/snabbdom production experience.

### Alternatives, honestly compared

- **Reagent** (2.0.1 on Clojars, ~7.6M downloads): the incumbent. Reagent 2.x is a substantial effort to survive React 19 concurrent rendering — ratom flushes now go through `flushSync`, tests were rewritten around async flushing ([reagent React19 notes](https://github.com/reagent-project/reagent/blob/master/doc/React19.md)); some community members consider Reagent "fundamentally incompatible with React 19's new internals," which prompted alternatives like Factor House's HSX/RFX ([factorhouse.io article](https://factorhouse.io/articles/beyond-reagent-migrating-to-react-19-with-hsx-and-rfx/)). Mature and familiar, but you inherit the whole React/npm treadmill for an app that doesn't need React's ecosystem.
- **UIx2** (`com.pitch/uix.core` 1.4.9, actively maintained, ~583k downloads): idiomatic macro-based interface to *modern* React with real hooks; the right choice **if** you want the React ecosystem (component libraries, virtualized lists) ([github.com/pitch-io/uix](https://github.com/pitch-io/uix)). For a mostly-server-shaped KWIC app it buys ecosystem you won't use, at the cost of npm/React versioning.
- **htmx / Datastar + server-rendered hiccup, no cljs at all**: strong contender for this app shape. The official **Datastar Clojure SDK** (`dev.data-star.clojure/sdk` 1.0.0-RC11, with ring and http-kit adapters) streams DOM patches over SSE, with the server owning all state and rendering hiccup ([github.com/starfederation/datastar-clojure](https://github.com/starfederation/datastar-clojure)); Anders Murphy has documented synchronous SSE with virtual threads in this style ([andersmurphy.com](https://andersmurphy.com/2024/10/07/clojure-synchronous-server-sent-events-with-virtual-threads-and-channels.html)); simpleui covers the htmx flavor ([github.com/whamtet/simpleui](https://github.com/whamtet/simpleui)). Zero cljs build, one language, one process. Cost: interactivity (KWIC context expansion, sort toggles, virtual scrolling over 100k hits) becomes a server round-trip each time, and client-side responsiveness on large result sets suffers.
- **Electric v3**: still **alpha** (`com.hyperfiddle/electric v3-alpha-*`, latest alpha May 2026) and moved to a **business-source license** — free for non-commercial/bootstrappers, otherwise commercial, with compile-time license activation ([Clojars](https://clojars.org/com.hyperfiddle/electric), [license change note](https://tana.pub/lQwRvGRaQ7hM/electric-v3-license-change)). Overkill and a licensing/maturity risk for a modest tool.
- **dumdom** (Replicant's predecessor, same author): 171 stars, last pushed 2024-08-23, last tag v2024.04.02 — effectively superseded by Replicant ([github.com/cjohansen/dumdom](https://github.com/cjohansen/dumdom)).

**Fit verdict for a KWIC app**: Replicant is a very good match — the app is "render a big table of server data, re-render on new pages/streamed batches," which is exactly Replicant's model; shared `.cljc` hiccup gives free SSR of first-paint results; nexus keeps event handling as data; no React/npm churn. The one honest rival is the no-cljs Datastar/htmx approach if you decide the interactivity really is minimal.

## 2. Backend

### Pedestal — current status

- **Versions**: 0.7.0 (2 Jul 2024), 0.7.2 (1 Nov 2024), **0.8.0 (20 Sep 2025)**, **0.8.1 (27 Oct 2025, latest stable)**, 0.8.2 in beta (beta-10 on Clojars) ([CHANGELOG](https://github.com/pedestal/pedestal/blob/master/CHANGELOG.md)). Actively maintained (primarily by Howard Lewis Ship).
- **0.7 changes**: Jetty 9→11, Servlet API 5, removed Immutant/Tomcat/AWS modules, OpenTelemetry-based metrics/tracing, JDK 11+, redesigned interceptor exception handling, `definterceptor` macro, clj-reload-friendly REPL workflow ([CHANGELOG](https://github.com/pedestal/pedestal/blob/master/CHANGELOG.md)).
- **0.8 changes**: the big one — **Pedestal connectors**, a lighter non-servlet abstraction; **Http-Kit is now a supported connector** alongside Jetty 12 (servlet code split into a `pedestal.servlet` module); Sawtooth is the default router; WebSockets became routable endpoints; JSON switched from Cheshire to **Charred**; Clojure 1.11+ minimum; many deprecated APIs removed ([CHANGELOG](https://github.com/pedestal/pedestal/blob/master/CHANGELOG.md), [connector reference](https://pedestal.io/pedestal/0.8/reference/connector.html), [Http-Kit reference](https://pedestal.io/pedestal/0.8/reference/http-kit.html) — the docs note http-kit "supports HTTP but not HTTPS, though it does support WebSockets and Server-Sent Events"; create via `io.pedestal.http.http-kit/create-connector`).
- **SSE**: first-class and connector-independent in 0.8. `io.pedestal.http.sse/start-stream` takes a "ready function" that receives a core.async channel; you `>!!`/`put!` event maps (`:name`, `:data`, `:id`); a put returning false signals client disconnect; heartbeats are scheduled via `alts!`+timeout with configurable buffer sizes; closing the channel closes the stream ([reference](https://pedestal.io/pedestal/0.8/reference/server-sent-events.html), [source io/pedestal/http/sse.clj](https://github.com/pedestal/pedestal/blob/master/service/src/io/pedestal/http/sse.clj)). Interceptors remain Pedestal's core differentiator and are well suited to per-session process management (attach session/process handle in an `:enter`, clean up in `:leave`/`:error`).

### ring + reitit + http-kit/jetty

- **http-kit**: stable **2.8.1** (2025-08-19), 2.9.0-beta3 (2025-11-04); actively maintained ([releases](https://github.com/http-kit/http-kit/releases)). SSE is done manually with `org.httpkit.server/as-channel` + `send!`, or via `ring-sse-middleware` ([github.com/kumarshantanu/ring-sse-middleware](https://github.com/kumarshantanu/ring-sse-middleware)); Ring 1.6+ async handlers and `StreamableResponseBody` also work ([Luca Grulla's writeup](https://www.lucagrulla.com/posts/server-sent-events-with-ring-and-compojure/)).
- **reitit**: 0.11.0-rc1 latest on Clojars (~5.3M downloads), 0.9.x/0.10.x stable line; fast data-driven routing, works with any ring adapter.
- **WebSockets**: available in both stacks (Pedestal 0.8 routable WebSockets incl. subprotocols on http-kit in 0.8.2-beta; http-kit natively; or taoensso/sente 1.23.0-RC1 for a higher-level channel abstraction). For one-directional streaming of query results, **SSE is simpler and sufficient** (auto-reconnect via EventSource, plain HTTP).

**Verdict**: given existing Pedestal experience, Pedestal 0.8.1 + the http-kit connector is current, light (no servlet stack), actively maintained, and has exactly the SSE machinery this app needs. ring+reitit+http-kit is equally viable but buys you assembly work Pedestal already did, and you'd give up interceptors.

## 3. Driving the child process (cqp) from the JVM

- **babashka.process** (`babashka/process` **0.6.25**, ~1.8M downloads) wraps `java.lang.ProcessBuilder` and is the idiomatic choice ([github.com/babashka/process](https://github.com/babashka/process)). Long-lived interactive pattern from the README: `(def p (process "cat"))`, write with `(io/writer (:in p))`, read `(:out p)` incrementally with `io/reader` + `read-line`/`line-seq`; `:shutdown destroy-tree` kills the tree on JVM exit; `deref` for exit code; explicit `:out` option warned as necessary to avoid buffer-deadlock when output is unconsumed. This maps directly onto CQP's line protocol: keep stdin open, write `command;\n`, read result lines until a sentinel.
- **Plain ProcessBuilder**: babashka.process is a thin veneer over it; if you drop down, Java 9+ gives `Process.onExit()` (CompletableFuture for supervision), `pid()`, `ProcessHandle.destroy()`/`descendants()` for cleanup ([JDK javadoc](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Process.html)). `redirectErrorStream(true)` is usually wrong here — keep stderr separate, since CQP writes errors there (see cglossa below).
- **Is a PTY needed?** No. A PTY is only needed when the child behaves differently off-TTY (libc block-buffering, disabled prompts). CQP explicitly provides **child mode** (`cqp -c`) designed for programmatic driving by web frontends — cglossa and CQPweb both use it over plain pipes ([CQP manual](https://cwb.sourceforge.io/files/CQP_Tutorial/), cglossa source below). If you ever do need a PTY on the JVM, **pty4j 0.13.10** (`org.jetbrains.pty4j/pty4j`, Maven Central, JetBrains, used by IntelliJ's terminal; latest release Jul 2025) is the standard option ([github.com/JetBrains/pty4j](https://github.com/JetBrains/pty4j)).
- **Pooling/supervision patterns**: cglossa (the main precedent, section 5) spawns a **fresh `cqp -c` per query batch** and uses CQP's *saved named queries* (e.g. `MYCORPUS11`) plus undump files to keep pagination state on disk between short-lived processes — statelessness via CWB's own persistence rather than a live process. The alternative your prompt implies — one long-lived child per session — works with babashka.process as above but needs: a per-session registry (map of session-id → process handle + lock, since one stdin/stdout pair is inherently single-threaded), idle timeout reaping, `onExit`-triggered restart, and a serializing queue per process (a `core.async` channel or an agent works well). A shared pool only helps if CQP startup cost matters and sessions don't need CQP-side state (macros, saved queries); given CQP starts in milliseconds and named queries persist to disk, **fresh-process-per-request is the simpler, battle-tested pattern** and what both cglossa and CQPweb do [CQPweb claim: unverified beyond its CWB-docs description]. A third route avoiding child processes entirely is `cqpserver` + the CQi binary TCP protocol, but CWB's own developers describe CQi as designed "within a few weeks... never found wide-spread use" ([CQi redesign notes](https://cwb.sslmit.unibo.it/doku.php?id=developers:cqi_redesign)).

## 4. Parsing

- **instaparse** 1.5.0 (`instaparse/instaparse`, 26M downloads, 2.8k stars, last pushed 2024-05-30 — mature/complete rather than abandoned; [github.com/Engelberg/instaparse](https://github.com/Engelberg/instaparse)). It shines for *grammars* (e.g. parsing user-entered CQP query syntax for validation/highlighting). For CQP's stable, line-oriented, tab/delimiter-separated *output*, a grammar is overkill: cglossa parses it with `str/split-lines` + positional destructuring (drop version banner line, first line = hit count, rest = KWIC lines), and a hand-rolled `line-seq` + `re-matches`/`str/split` parser is faster, streams naturally, and fails more legibly. Recommendation: hand-rolled for the wire protocol; instaparse only if you build a query-language front end.
- **ANSI handling**: the standout is **lambdaisland/ansi 0.2.37** — parses ANSI SGR escape sequences directly **to hiccup** (spans with inline styles), supports 8-bit and 24-bit color, is `.cljc` (works JVM- and browser-side), and ships `hiccup-xform`, a stateful transducer that maintains terminal state across **chunked/streamed input** — a precise fit for streaming CQP output with `set Colour on` through SSE into Replicant hiccup ([github.com/lambdaisland/ansi](https://github.com/lambdaisland/ansi), [Clojars](https://clojars.org/lambdaisland/ansi)). Others found on Clojars/GitHub: `io.logicblocks/antsy` 0.0.17-RC9 (generating ANSI, not parsing), `com.github.strojure/ansi-escape` 1.0.2-08 (constants), various `clansi` forks (colorizing output), `venantius/glow` (Clojure-source syntax highlighting to ANSI/HTML — different problem). Simplest alternative: run CQP without color and skip ANSI entirely; CQP's `show`/`set` options control markup, and you can have it emit its own delimiters.

## 5. Existing Clojure corpus-linguistics / CWB work

- **cglossa** ([github.com/textlab/cglossa](https://github.com/textlab/cglossa)) — Tekstlab (University of Oslo)'s Clojure/ClojureScript rewrite of Glossa, the corpus search and results-management UI over CWB. Stack (from [project.clj](https://github.com/textlab/cglossa/blob/master/project.clj)): Clojure 1.8, Reagent 0.6, http-kit 2.2, Compojure + Ring, transit-clj, core.async, Korma+MySQL for metadata, me.raynes/conch for processes — a 2016-era stack, last pushed 2021, ~1,100 commits, MIT/EPL. **How it talks to CWB** (verified in [src/clj/cglossa/search/cwb/shared.clj](https://github.com/textlab/cglossa/blob/master/src/clj/cglossa/search/cwb/shared.clj)): `run-cqp-commands` spawns `cqp -c` via conch with `LC_ALL` set for the corpus encoding, joins commands with `;\n`, feeds them on stdin, closes stdin, slurps stdout/stderr, asserts stderr blank, drops the CQP version banner line, optionally reads a count line, and regex-scans for `PARSE ERROR|CQP Error`. Metadata filtering is done in SQL producing corpus-position dump files fed to CQP via `undump`. **Maturity assessment**: abandoned but complete — the best existing reference implementation for CQP-driving patterns, query construction (`within s`, aligned multilingual queries, named saved queries `MYCORPUS<id>`), and KWIC result views; do not depend on it as a library.
- **fglossa** ([github.com/textlab/fglossa](https://github.com/textlab/fglossa)) — Tekstlab's current Glossa is an **F# rewrite**, pushed as recently as 2026-01-12; cglossa is superseded upstream. Worth mining for current CQP interaction patterns.
- **cqp-clj** ([github.com/emanjavacas/cqp-clj](https://github.com/emanjavacas/cqp-clj)) — a Clojure/Java CQi client following the CQi spec: 0 stars, `0.1.0-SNAPSHOT`, GPL-3, dead since 2015-12. Proof of concept only.
- **Clojars searches** for "cwb", "cqp", "concordance": **zero published artifacts**. GitHub searches (`cwb language:clojure`, `cqp language:clojure`, `concordance language:clojure`, "corpus workbench") found only toy word-frequency projects and non-Clojure hits (PolMine/RcppCWB for R, python cqi-py [github.com/Pevtrick/cqi-py](https://github.com/Pevtrick/cqi-py)). **Conclusion**: no maintained Clojure CWB/CQP library exists; you will write the (small) driver yourself, with cglossa as the template.

## 6. Supporting choices

- **SSR/hiccup**: `hiccup/hiccup` **2.0.0** final (weavejester, 30M downloads; 2.x adds auto-escaping via `hiccup2.core`) ([Clojars](https://clojars.org/hiccup)) — or skip it and use **Replicant's own `replicant.string/render`** so server-rendered pages and client views share one `.cljc` codebase, which is the stronger choice here.
- **Wire format**: **Transit** (`com.cognitect/transit-clj` 1.0.333, transit-cljs counterpart) round-trips keywords/namespaced keys losslessly into cljs — natural when both ends are Clojure and payloads are hiccup-shaped/EDN-shaped data. **JSON**: `metosin/jsonista` 1.0.1 (Jackson-based, 14M downloads) or `com.cnuernber/charred` 1.042 (pure-Clojure, zero-dep, fast — what Pedestal 0.8 itself adopted). Note SSE `data:` lines are text; Transit-as-JSON works fine inside them. Recommendation: transit for app data; charred if you need plain JSON endpoints (aligns with Pedestal's own dependency).
- **Build**: deps.edn + **shadow-cljs 3.5.0** (`thheller/shadow-cljs`, 6.9M downloads) is the standard cljs setup; shadow-cljs reads dependencies from deps.edn via `:deps {:aliases [...]}` in `shadow-cljs.edn` ([shadow-cljs user guide](https://shadow-cljs.github.io/docs/UsersGuide.html#deps-edn)). One `:app` browser build + `:dev-http`; the JVM backend runs from the same deps.edn.
- **Dev workflow**: **portal 0.67.2** (`djblue/portal`, actively maintained, pushed 2026-08) for tap>-based inspection on the JVM side; **dataspex 2026.06.3** for client-side state and Nexus action-log inspection; **portfolio 2026.03.1** for developing KWIC row/table components against canned CQP output without a running backend; standard nREPL/CIDER/Calva.

## Recommended stack

| Layer | Choice | Version |
|---|---|---|
| HTTP server | Pedestal (connector API) + Http-Kit connector | `io.pedestal/pedestal.connector` + `io.pedestal/pedestal.http-kit` **0.8.1**, http-kit 2.8.1 |
| Streaming | Pedestal SSE (`io.pedestal.http.sse/start-stream`, core.async) | bundled |
| Child process | babashka.process (`cqp -c` per query batch; CQP named queries/undump for pagination state; `:shutdown destroy-tree`; per-session serialization only if you later switch to long-lived children) | `babashka/process` 0.6.25 |
| Output parsing | hand-rolled `line-seq`/`str/split` parser; `lambdaisland/ansi` 0.2.37 only if you keep CQP color output | — |
| Frontend | Replicant + Nexus (+ Dataspex, Portfolio in dev) | `no.cjohansen/replicant` 2026.07.1, `nexus` 2026.08.1, `dataspex` 2026.06.3, `portfolio` 2026.03.1 |
| Shared rendering | `.cljc` views rendered by `replicant.string/render` (SSR) and `replicant.dom/render` (client) | bundled with Replicant |
| Wire | transit-clj/transit-cljs (app data); charred for any plain-JSON needs | `com.cognitect/transit-clj` 1.0.333, `com.cnuernber/charred` 1.042 |
| Build/dev | deps.edn + shadow-cljs; portal | `thheller/shadow-cljs` 3.5.0, `djblue/portal` 0.67.2 |

Rationale: leverages existing Pedestal expertise on a freshly modernized (Sep–Oct 2025) 0.8 release whose connector/SSE model is exactly shaped for streaming query results; Replicant gives React-free data-driven rendering with shared server/client hiccup, ideal for a mostly-server-shaped KWIC UI; the CQP driver follows the proven cglossa pattern with a modern process library; no dependency in the stack is unmaintained.

## Honest alternative

**No-ClojureScript hypermedia stack**: ring + reitit 0.11.x + http-kit 2.8.1, hiccup 2.0.0 SSR, and **Datastar** (`dev.data-star.clojure/sdk` + `http-kit` adapter, 1.0.0-RC11) streaming server-rendered DOM patches over SSE ([datastar-clojure](https://github.com/starfederation/datastar-clojure)). One language, one process, no cljs build, no client state, and streaming KWIC rows is just streaming HTML fragments. Choose it if you conclude the interactivity ceiling (server round-trip per interaction; weaker story for client-side sorting/virtual scrolling of very large result sets) is acceptable for your users; choose the Replicant stack if snappy client-side manipulation of loaded concordance pages matters.
